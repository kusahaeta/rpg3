スクリーンショットの 02〜06 は `ios/screenshots/` から両はしの余白（iPhone の安全領域の帯）を切り落として 16:9 にし、1920×1080 に縮めた。iPhone の 2868×1320 は横長すぎて（2.17:1）Play では受け付けない。

タイトル（`01-title.jpg`）とフィーチャー グラフィックは、夕暮れの空にしたあと（2026-10-25）に `tools/shoot-title.mjs` で撮った。撮りなおすときは：

```
PORT=8937 node .claude/serve.js
node tools/shoot-title.mjs 01-title.png 1.5 start      # 1920×1080
node tools/shoot-title.mjs title-4k.png 3 nostart      # 3840×2160（フィーチャー グラフィック用）
```

紹介動画は `promo/google-play-1920x1080.mp4`（30 秒）。Play Console には YouTube の URL を入れるので、YouTube に上げて（公開か限定公開。広告なし）その URL を「プレビュー動画」に入れる。中身と作りなおし方は App Store のプレビューと同じ（`ios/AppStore.md` の「プレビュー動画」）で、まん中の 16:9 だけを切り出している。

フィーチャー グラフィックは、3840×2160 の上下をまん中で切って 3840×1875 にし、1024×500 に縮める（樹冠が多く入るので、下に寄せるよりまん中がよい）。ほかの場面を撮りなおすときは `ios/AppStore.md` の撮り方で、画面を 16:9 にして撮る。

## アプリのコンテンツ（ポリシーの申告）

- **プライバシー ポリシー**：上の URL
- **広告**：含まない
- **アプリのアクセス権**：すべての機能が制限なしで使える（ログインなし）
- **コンテンツのレーティング**（IARC のアンケート）：カテゴリは「ゲーム」。暴力は「アニメ・ファンタジーの暴力」（ねこやモンスターの戦い、血は出ない）。性的な内容・ホラー・ギャンブル・薬物・下品な言葉・ユーザーどうしのやりとり・位置情報の共有・デジタル商品の購入はすべて「いいえ」
- **ターゲット ユーザー**：13 歳以上の年齢層を選ぶのが手軽。13 歳未満を含めると「ファミリー ポリシー」の審査が加わる（広告もデータの収集もないので満たせるはずだが、項目が増える）
- **データ セーフティ**：「収集・共有するデータはない」。外と通信しない（`fetch`・`XMLHttpRequest`・`WebSocket` も外の URL もなく、WebView はゲームの外へ移らない）。セーブは端末の中（WebView の localStorage）。Android の自動バックアップ（`allowBackup`）でユーザー自身の Google アカウントに残るのは「収集」に入らない
- **広告 ID**：使わない
- **金融・健康・ニュース・政府のアプリ**：どれでもない

## 出すまでの手順

1. [Play Console](https://play.google.com/console/) でデベロッパー アカウントを作る（登録料 25 ドル、本人確認あり）
2. このリポジトリで `sh android/tools/make-upload-key.sh` を 1 度だけ実行し、アップロード鍵を作る。鍵は `~/.android/nyanko-upload.jks`、パスワードは `android/keystore.properties`（どちらもリポジトリに入らない）。鍵とパスワードは別の場所にも控える
3. `sh android/tools/release.sh` で AAB を作る。`versionCode` は main のコミット数（iOS のビルド番号と同じ）、`versionName` は `app/build.gradle` の `1.0`
4. Play Console → アプリを作成 → 上の表のとおりに入れる。アプリの署名は「Google Play アプリ署名」（はじめの AAB を上げると自動で有効になる）
5. まず「内部テスト」に AAB を上げ、手元の Android で入れて通しで遊べるかを確かめる
6. 個人のアカウント（2023-11-13 以降に作ったもの）は、**クローズド テストに 12 人以上が 14 日続けて参加**しないと製品版に出せない。テスターの Google アカウント（Gmail）を集めてクローズド テストに招き、14 日たったらダッシュボードから「製品版へのアクセス」を申し込む
7. 製品版のリリースを作って審査に出す（数時間〜数日）

## つまずきやすいところ

- **向ける API**：2026-08-31 から、新しいアプリと更新は API 36（Android 16）向けでないと出せない。毎年 8 月末に 1 つ上がるので、そのたびに `app/build.gradle` の `compileSdk`・`targetSdk` を上げる
- **戻るキー**：API 36 向けにすると、Android 16 では `onBackPressed` が呼ばれない。`MainActivity` で `OnBackInvokedCallback` も登録して、どちらでも裏に回るだけにしてある
- **タブレット**：Android 16 は大きい画面でアプリの向きの指定を無視するが、ゲーム（`android:appCategory="game"`）は対象外。これで横画面のまま遊べる
- ビルドは Android Studio の JDK 17 で通る。Android Studio で開くときは、AGP 8.13 に合う新しい版（2025 年以降）に上げておく
